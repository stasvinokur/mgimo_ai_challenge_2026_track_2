# Корпус вымышленных положений

Все документы написаны для конкурсного концепта, без копирования реальных положений. Источник правил — doc-1 §7–8 и каталог `scripts/fixtures/requests.ts`.

| Slug (имя файла без .md) | Документ | Ключевые ссылки |
|---|---|---|
| `certificates` | Справки и заявления | `/regulations/certificates#p-3-2` — по месту требования, включая работодателя; `#p-3-3`–`#p-3-5` — другие справки; `#p-4` — заявления и вопрос; `#p-5`, `#p-5-1`, `#p-5-2` — статусы |
| `scholarship` | Стипендии | `/regulations/scholarship#p-2` — академическая и повышенная |
| `assessment` | Текущий контроль и итоговая оценка | `/regulations/assessment#p-2` — веса и формула; `#p-3` — пороги 55/70/86; `#p-4` — индикаторы |
| `retakes` | Пересдача и академическая задолженность | `/regulations/retakes#p-2` — заявление; `#p-3` — стипендия при долге |
| `academic-leave` | Академический отпуск | `/regulations/academic-leave#p-2` — 10 рабочих дней |
| `schedule` | Расписание и его изменения | `/regulations/schedule#p-2` — виды изменений |
| `attendance` | Посещаемость, уважительные причины и баллы активности | `/regulations/attendance#p-2` — QR; `#p-3` — причины; `#p-4` — мероприятия; `#p-5` — баллы |
| `faq` | Частые вопросы в деканат | `/regulations/faq#p-3` — подтверждение отправки человеком |

Формат: один заголовок `# Название`, затем преамбула, начинающаяся с точной пометки «Вымышленное положение конкурсного концепта». Далее заголовки `## 2 Название пункта`, `### 3.2 Вложенный пункт` (глубина заголовка 2–6). Номера — положительные целые компоненты через точку, без ведущих нулей и завершающей точки. Пропуски номеров допустимы; существующие номера и slug не переименовываются: это публичные ссылки для подсказок и ассистента.

Номер становится `section`; якорь — `p-` и номер с заменой точек на дефисы (`3.2` → `p-3-2`). Пункт `0` зарезервирован: хранит название документа в `title` и преамбулу в `body`. Остальные записи хранят название и markdown-текст пункта. Порядок естественный: 2, 2.1, 2.2, 2.10, 3. Заголовки без номера, повторные номера, пустые номера/названия/тексты и незакрытые блоки кода останавливают сид до изменения данных. Заголовки внутри ограждённого блока кода считаются текстом.

Сид читает все `.md`, кроме README, до записи. Ключ записи — `demo:regulation:<slug>:<section>`. В одной транзакции он обновляет пункты по `seed_key` и удаляет отсутствующие в корпусе записи только с префиксом `demo:regulation:`. Пользовательские записи с null или иным `seed_key` не затрагиваются. Старые два demo-пункта заменяются новым корпусом. Схема БД не меняется. Runtime читает только `regulation_chunks`: `content/` нужен исключительно стадии сида.

Ссылки в текстах только внутренние (`/…` или `#…`), изображения не используются. UI рендерит markdown через react-markdown с отключённым HTML и фильтром внутренних ссылок. Поисковый фрагмент использует текстовые маркеры `[[[` и `]]]`; интерфейс рисует `<mark>` и экранирует весь текст. Вывод ts_headline никогда не вставляется как HTML.
