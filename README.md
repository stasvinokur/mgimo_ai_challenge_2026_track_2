# «Пульс — цифровой деканат»

> Конкурсный концепт MGIMO×AI Challenge, номинация «Вайб-кодинг». Не официальный сервис МГИМО. Все данные вымышлены.

Личный кабинет студента. Главный экран отвечает на три вопроса: что сейчас, что требует моего действия и что дальше.

На стенде экран входа не показывает пароли, а у демо-аккаунтов свои пароли, не те, что видны в ролике. Иначе по ним заходили бы боты. Данные Анны и Тимура разные, и чужие объекты не открываются даже по прямой ссылке. Всё, что посетители меняют под общими демо-аккаунтами (баллы, заявки, отметки, записи в очередь), примерно через час возвращается к исходному, чтобы сценарий жюри не ломался. Язык интерфейса (русский или английский) выбирается на экране входа и в «Профиле» → «Настройки», там же — режимы доступности.

## Что умеет кабинет

**Обязательное ядро:**
- вход и профиль;
- расписание с заметными переносами;
- успеваемость;
- заявки и справки со статусом «как у посылки»;
- уведомления.

**Сверху:**
- ИИ-ассистент «Спросить или сделать»: отвечает по вашим данным и вымышленным положениям деканата, готовит черновик заявки, а отправляете вы. В профиле есть журнал: что ИИ ответил и предложил и что вы подтвердили сами;
- «Что можно сделать?»: от предупреждения о долге или риске — к понятному шагу и готовому обращению в деканат;
- «Сводка дня» на «Сегодня»: несколько фраз о дне, кнопка «Послушать» читает их собственным синтезом речи «Пульса» (Silero на своём сервере, без внешних сервисов), а без него — голосом устройства;
- кабинет сотрудника деканата;
- кабинет преподавателя: посещаемость по меняющемуся QR на экране аудитории и личные баллы активности студента;
- освобождение на время хакатона или олимпиады: после одобрения деканата пропущенные пары сами становятся уважительными;
- «Что если?» и прогноз стипендии;
- PDF-справка с QR-проверкой;
- поиск по кабинету и палитра команд ⌘K;
- установка на телефон с офлайн-расписанием;
- вход по ключу доступа (отпечаток пальца или Face ID) и уведомления на телефон, даже когда кабинет закрыт;
- электронная очередь за бумажной справкой: талон, вызов в окно, выдача;
- зачётка с историей изменений: преподаватель ставит баллы с причиной, студент видит, что и почему изменилось;
- развилка «сдать или пропустить» в «Что если?» и «Первые шаги» для первокурсника;
- английский интерфейс кабинета студента и режим доступности: крупный текст, высокий контраст, меньше движения.

## Как создавался «Пульс»

Весь продуктовый код написали ИИ-агенты:
- **Codex** (`gpt-6.1-sol`) — исполнитель, по одной задаче за запуск. Перекрёстное ревью milestone провела более сильная модель `gpt-6-astra`;
- **Claude Code** — архитектор, оркестратор, проверяющий и ревьюер. Каждую работу исполнителя он проверял сам: тесты, браузер на 360 px, аудит безопасности;
- **связь между ними** — только через задачи в Backlog с критериями приёмки, планом, заметками и доказательствами.

Правила исполнителя лежат в [`AGENTS.md`](AGENTS.md). Его раздел «Известные ошибки ИИ → правило» пополнялся после каждой пойманной ошибки. Весь процесс, ключевые промпты, ошибки ИИ и как их поймали — в [`Pulse-process.pdf`](Pulse-process.pdf).

## Стек и архитектура

- **Приложение.** Next.js 16 и React 19 на TypeScript 7, Tailwind 4 и shadcn/ui, шрифт Golos Text лежит локально.
- **Данные.** PostgreSQL 18 через Drizzle, валидация zod, пароли argon2id, сессии хранятся на сервере.
- **ИИ.** Ассистент на Vercel AI SDK 7 и облачных моделях Ollama (`glm-5.3-flash`, запасная `gpt-oss:120b`). Модель вызывается только с сервера, аргументы тулов проверяет zod, отправку заявки подтверждает человек.
- **Офлайн и телефон.** PWA на Serwist, уведомления Web Push (ключи VAPID только на сервере), вход по ключу доступа (`@simplewebauthn`).
- **Языки.** Русский и английский: словари без сторонних библиотек, выбор хранится на устройстве.
- **Голос.** «Сводку дня» озвучивает Silero TTS `v5_5_ru` в отдельном сервисе `tts` на Python и PyTorch: своя внутренняя сеть без доступа к базе и интернету, зависимости закреплены по хэшам. Модель распространяется по лицензии CC BY-NC 4.0, для некоммерческого прототипа это допустимо. Подробно — [`infra/tts/README.md`](infra/tts/README.md).
- **Чистая архитектура.** `src/domain` → `src/application` → `src/infrastructure`; страницы (`src/app`, `src/ui`) вызывают сценарии через `src/composition`. Правило слоёв проверяют dependency-cruiser и Biome.
- **Сборка.** Docker с multi-stage сборкой и compose. CI на GitHub Actions — [`.github/workflows/ci.yml`](.github/workflows/ci.yml): проверки, поиск секретов, образы, e2e против собранного образа. Запускается вручную: Actions → CI → Run workflow.

## Запуск локально

Нужен Docker с Compose.

1. Скопируйте `.env.example` в `.env` и заполните обязательные поля: `POSTGRES_PASSWORD`, `DATABASE_URL` (хост `db`), `APP_ORIGIN=http://localhost:3000`, `IMAGE_TAG=local`, `COMPOSE_FILE=compose.yaml`.
2. Выполните `docker compose up --build --wait`.
3. Откройте <http://localhost:3000>. Кнопки «Войти как …» на экране входа подставляют пароли демо-аккаунтов по умолчанию.

Миграции, сид демо-данных и «живые» даты применяются автоматически. Без ключа Ollama ассистент работает в честном упрощённом режиме: отвечает с пометкой «Ответ без ИИ». Push включается необязательными `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT`. Озвучка «Сводки дня» собственным голосом включается профилем: `docker compose --profile tts up --build --wait` и `TTS_URL=http://tts:8000` в `.env`; без них кабинет читает сводку голосом устройства. Вход по ключу доступа работает на `localhost` или на домене с HTTPS, по IP-адресу браузер его не разрешает.

## Сервер

Порты 80 и 443 держит общий входной Caddy в `/opt/edge` ([`infra/edge/`](infra/edge/)): на одном VPS может жить несколько проектов, каждый на своём поддомене или в папке общего домена. На стенде «Пульс» живёт в папке `/dekanat` домена `mgimo.stasvinokur.ru`, в корне — витрина решений. Приложение собирается с `BASE_PATH=/dekanat`, а Caddy передаёт ему `/dekanat` и `/dekanat/*` без отрезания префикса. «Пульс» подключается к Caddy через сеть `edge` ([`compose.server.yaml`](compose.server.yaml)), порты приложения и базы наружу не опубликованы. HTTPS-сертификаты Caddy получает сам.

1. На сервере нужны Docker с Compose и DNS-запись домена на VPS.
2. Создайте `/opt/pulse/.env` (права 600) по `.env.example`:
   - `COMPOSE_FILE=compose.yaml:compose.server.yaml`, `APP_DOMAIN=<домен>`, `APP_ORIGIN=https://<домен>` (origin без пути);
   - `BASE_PATH=/dekanat` — папка кабинета; пусто — кабинет занимает весь домен;
   - `COMPOSE_PROFILES=tts` и `TTS_URL=http://tts:8000` — для собственного голоса;
   - `DEMO_LOGIN_HINTS=off` и `DEMO_ACCOUNT_PASSWORDS=anna:…,timur:…,marina:…,oleg:…` — для публичного стенда: экран входа без паролей и свои пароли демо-аккаунтов.
3. С компьютера разработчика: `DEPLOY_BUILD=1 VPS_HOST=<адрес> VPS_USER=root infra/deploy.sh <полный SHA коммита>`. Скрипт доставит код выбранного коммита, соберёт образы на сервере, применит миграции, подключит папку к общему Caddy и проверит `https://<домен>/dekanat/api/health` и экран входа.

Откат — тот же скрипт с предыдущим SHA. Резервная копия базы снимается каждую ночь сервисом `backup`, демо-данные восстанавливаются каждый час сервисом `scheduler`.

## Для разработчика

- `pnpm check` — lint, typecheck, правило слоёв, тесты (unit, application, integration на PostgreSQL из `DATABASE_URL`) и сборка.
- `pnpm test:e2e` — Playwright, проекты `mobile-360` и `desktop`.
- `pnpm db:migrate` и `pnpm db:seed` — миграции и сид демо-аккаунтов. Повторный сид не создаёт дубликатов, пользовательские записи сохраняются.
- `pnpm demo:refresh` — возвращает демо-сценарии к исходным и обновляет даты демо-записей относительно текущего дня в Москве.
- `pnpm docker:dev` — только база для разработки на `127.0.0.1:5432`.
